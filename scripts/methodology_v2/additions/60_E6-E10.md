### E6 · 把 GitHub Actions 当「外网之手」用（2026-10-23 T29-U18/U19 起；10-29 U131 快照并入）

- **分工**：沙箱 = 读写仓库、算、写文档、`web_search / fetch_page`；运行器 = 抓客户站 / 下载大文件 / OCR / DNS 批量 / 快照。四个工作流：`customer-watch`（cron 02:23Z + 手动，监控 + 顺手补快照，自动提交）、`saga-clients-snapshot`（全量快照，手动）、`drive-smartbyte-ingest`（大文件入库，手动）、`smartbyte-crawl`（官网抓取，手动）。
- **触发杠杆**：cron；Simon 网页点 Run workflow（可选 layer，大小写不敏感；ALL）；改 `RUN` 文件 push（入库管道）。沙箱**不能**：推 `.github/workflows/`（要改 workflow → 把完整 YAML 写进 docs 让 Simon 粘贴）、`gh`（403）、curl 外网。
- **并发纪律**：机器人提交随时会落到本分支 → 每次推送前 `fetch + pull --rebase`；冲突时机器人文件取 theirs；不要连续手动触发多次；在 Actions 跑的时候**不空转等**，去干别的（T13–T16 规则）。
- **消费端幂等**：运行器产物都带 `fetched_at` / 时间戳，沙箱消费脚本按它只消费一次（C11）。

### E7 · 台账的幂等配方与踩过的坑（长期积累；10-29 15:56Z 新坑）

- 对话全记录：逐字（含错别字）、append-only、时间来自 `date -u`；Simon 的消息时刻拿不准就写「（约）」或「会话内，精确时刻未提供」，**不编**。
- 总账 PR 行：五格（编号 ｜ 轮次 + 时间 + 原话 ｜ 转述 ｜ 性质 ｜ 状态 + 位置）；PR 行在文件里**分两块**（老块 PR-02-44…46 在 INH 表附近）→ 新行插在**编号最大**的 PR 行之后，不是「文件里最后一条 PR 行」之后（10-29 15:56Z 插错一次）。
- Q 行：六格；编号 = 现有最大 + 1；默认值写明；裁定后只填「结果」不删行。
- README：进度是文件末尾的编号列表（`N. **标题（轮次，时刻Z）。** 正文`），插在最后一个编号项之后。
- 变更日志：只由 `scripts/changelog.py` 生成（`timeout 900`，≈140 s）。
- 一律：存在性检查（`if row not in s`）而不是 `assert count==1`；写完 `grep -c` 验证；一文件一步。可复制代码在 `docs/方法论_V2_像素级SOP_2026-10-29.md` §3.1。
