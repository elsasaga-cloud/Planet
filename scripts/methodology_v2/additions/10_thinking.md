## Ⅰ. 怎么分析、怎么决定（思维方法 M1–M14，2026-10-29 新增）

> A–G 讲的是「每类活怎么干」；这一章讲的是干任何活之前**脑子里先过的那套东西**。每条都来自 10-19 → 10-29 真实踩出来的经验，附诞生时刻。弱一点的 Agent 把这 14 条当检查表，强一点的当习惯。

### M1 · 先复述，再动手：任务 = 一句话 + 可验证的验收标准

- **解决什么**：最贵的错不是做错一步，是整件事理解错了（例：2026-10-29 15:4xZ T29-U133，把「优化方法论（怎么工作、怎么分析）」做成了一本命令手册——因为动手前没把「方法论」这个词的定义写下来跟 Simon 的原话对一遍）。
- **怎么做**：① 逐字读原话，圈出动词（优化 / 更新 / 出 / 查 / 告诉我）和宾语（哪份文件、哪批客户）；② 把宾语在仓库里**打开看一眼**（它是什么性质的东西，别凭名字猜）；③ 写一句「Simon 要的是 X，做到 Y 算完」，Y 必须能用命令或数字验证（「七维缺口表每户为空」「名册 2,045 户每户有复核结论」）；④ 有两种读法且结果差很远 → 按 T07 不问，但**先做便宜的那种 + 在回复第一行写出你的理解**，让他能一句话纠偏。
- **坑**：用上一轮的记忆代替读文件；把「像不像我最近做的事」当成理解；验收标准写成「尽量」「更好」这种测不了的词。

### M2 · 证据分级与引文纪律

- **解决什么**：客户档案、底数、信稿全靠事实；一条编出来的邮箱或价格会让整封信作废、让 Simon 丢脸。
- **怎么做**：证据从硬到软五级——① 一手单据（PI / 来信原文 / 银行水单 / 官方登记页）② 对方官网原文（页脚法定名、商品页、About）③ 官方 API / 公开数据库（Companies House、ARES、SAM 镜像）④ 第三方摘要（D&B / ZoomInfo / LinkedIn 摘要：只取职务、人名、**量级**）⑤ 推断（必须标「推定」）。每条事实 = `claim + quote(≤300 字原文) + url + date`；没有就写 `待补证`，不写进对外稿。**Simon 的备注是我方判断，不是客户事实**（不能当 pass 依据）；「想象力用在维度上，不用在事实上」（C2）。
- **坑**：把搜索摘要里的营收 / 人数当精确数；同名公司不对地址就写入；把 Netaş 单据总额 USD 545 当单价（U132 自查改正）；价格锚从记忆里写而不是从 `data/价格主表_HRUI.csv` 取。

### M3 · 把主观判断变成「规则 + 旋钮 + 模拟」，再让 Simon 选

- **解决什么**：「这家算 A 还是 B」如果每户靠感觉，三库 7,000 户永远对不齐，Simon 也没法一句话改口径。
- **怎么做**（A/B v5 的实际过程，2026-10-29 11:53Z T29-U125）：① 先**诊断现状**出数字表（A 90 户里 40 户邮件层 0 真人回复；B 里成单 51 户 > A 的 18 户；WA 关系 B 是 A 的 6 倍）→ 问题被量化；② 写成**可机检规则**（A1 复购或绑定 ≥ 中度 / A2 成单 + 真人往来 / A3 真人往来 + 对位 + 四主区 + 坐实或自牌 / A4 Simon 点名 / A5 自牌 + 对位 + 真人往来 / A6 真回 ≥3 + 对位；B1–B6 同理）；③ **三口径全量模拟**（严 / 宽 / 宽留冷）输出 A/B/C 总数 + 流动矩阵（A 留 A / A→B / A→C / B→A / B→B / B→C）+ 分区域分布；④ 给 Simon 一张表 + 我的建议（宽 A + 留冷 B）+「旋钮都在脚本顶部，一句话改数重跑」；⑤ 落地时每户理由写**命中的规则号**，以后换口径能机器重算。
- **坑**：规则里混进测不了的词（「有潜力」）；只给一个口径让他选「是 / 否」；模拟表不给流动矩阵（他最关心「谁被降了」）。
- **文件**：`docs/AB判定_新标准_讨论稿_2026-10-29.md`、`data/saga_clients/AB新标准_模拟_2026-10-29.csv`。

### M4 · 机器只做刚性，人只判模糊（分层筛选）

- **解决什么**：几千户要过一遍，机器全判会错杀，人全判做不完。
- **怎么做**：先定义「什么是机器可验证的刚性条件」（C 池闸 0 只认三条：无任何联系路径 / 退信且所有域 DNS 死且无电话 WA / 明确拉黑或造假）+ **例外优先**（成单 / 样品 / 真回 / WA / 乌克兰 → 不管命中什么都转人判）；人判用固定五问三选一（活着吗 / 卖什么角色 / 对位吗 / 地区 / 路径），默认值 = 最保守（keep_C）。**「任何需要判断的都不进机筛」**；「Spam」「不再跟进」「不相关」这类备注都是我方当年的决定，不是客户拒绝，不刚性。
- **Simon 的否决是校准器**（2026-10-29 02:51Z T29-U117）：乌克兰 53 / 巨头运营商 48 / 品类不对位（光端机 / DWDM / 光模块 = 他本职能用）/「研究后定 C」44——都不是永久 pass。刚性标准**宁漏勿错**。
- **文件**：`docs/C池三闸筛选_方案_2026-10-29.md` §2–§3；`scripts/saga_clients/sieve.py --gate0`。

### M5 · 可逆优先：不可逆的动作标准最严，其余都要写「怎么回来」

- **怎么做**：等级升降、打回 C、并档、改国——全部可逆，且理由里必须有「可逆条件 = 补到邮箱 / 回信 / 收款路径解决即回 B」；改动留历史（`override_history`、overrides `from`、CSV 备注追加不覆盖）。唯一不可逆 = 永久 pass（「一旦入选 永不考虑」），所以它只认三条刚性。
- **坑**：为了「干净」把拿不准的户 pass 掉；删行、覆盖旧值、重命名文件（都让历史断掉）。

### M6 · 负面结论要第二次独立验证

- **解决什么**：机器说「死了」经常是它自己超时。2026-10-29 早上一轮 DNS 体检把 mreit.co.kr / hightrade-international.com / arcanlibya.com 判成异常，14:48Z 复查全部正常——差点打回 3 户。
- **怎么做**：任何「不可达 / NXDOMAIN / 404 / 退信」在成为打回或 pass 理由前，换时间或换方法再查一次（DNS 用 MX + A + NS 三条；网页用搜索摘要看是否仍在营；邮箱看有无别的域 / 私人箱）；运行器抓快照失败要**连续两晚**再加 DNS 死才进打回候选；404 的仓库先查是改名 / 转私有 / 删除（U79 追问）。
- **坑**：把一次工具失败写成客户事实；在高并发那一轮直接下结论。

### M7 · 缺口盘点法：把「都搞完了吗」变成一张维度表

- **解决什么**：Simon 问「这些 A/B 都深挖过了吗？加厚 审核 交叉检查等等」（2026-10-29 14:22Z T29-U131），口头回答「差不多」没有意义。
- **怎么做**：① 列出「搞完」包含的全部维度（研究深度 / 登记底数 / 官网快照 / 域名·MX / 邮箱·具名 KP / 复核 / 跨库重复 = 七维）；② 一户一行机器填表 → 「还缺什么」列；③ 每种缺口映射到一个动作（研究 → 加厚；登记 → 底数；快照 → Actions；域名 → 体检 + 复核；KP → 挖 KP；复核 → LT-R；重复 → 并档）；④ **完成 = 表空，或每个剩余缺口有「为什么不做 / 谁来做 / 什么时候」**（例：~1,100 户快照交给 customer-watch 夜跑）；⑤ 定义什么**不算缺口**（WA 客户没邮箱、公开页只有表单），免得无限做下去。
- **通用性**：任何「全部 / 都 / 每一个」类问题先建维度表再回答；A 级「齐」= 七维全满（136 户）。
- **文件**：`scripts/lt_gap_audit.py` → `docs/长期客户群_深挖缺口_2026-10-29.md` + CSV。

### M8 · 幂等、两遍跑、渲染即验证

- **怎么做**：所有写入脚本带去重键（TAG / 批次 / `fetched_at` / 编号守卫），**第二遍跑必须 0 写入**；写完立刻渲染 + 审计，让机器替你检查（`audit_full` hard 0、`audit.py` 四个 0、名册数字）；台账脚本用存在性检查而不是 `assert count==1`（后者一崩整段不跑）。
- **坑**：10-29 15:56Z 总账 PR 行按「文件里最后一条 PR-02」插入，结果插进了老块（PR 行分两块）——改为按**编号最大**的行插；`str.replace` 后不 `grep -c` 验证。

### M9 · 预算与止损：一查未得即停，两把尺决定做不做

- **怎么做**：一户一次检索（`web_search depth 1` 摘要优先；页面只读第 0 块），未命中记 `未得 + 日期` 即停，不换五个站死磕；每轮 20–40 户；不可查的（个人邮箱 / 仅 WA / 无名）不烧预算。做不做任何事用两把尺：**省 Simon 的时间吗？有长期复利吗？**（T29-U29）两样都不沾 → 不做或最小版 + 立 Q。
- **坑**：为了把表填满而去查明知查不到的国家（GR / CY / AE / SG 官方库不公开，已关闭）。

### M10 · 批处理设计模式：队列 → 批文件 → 共用库 → 日志 → 名册

- **解决什么**：复核 1,219 户、底数 1,487 户、研究卡 1,096 张，靠一次性脚本会乱、会重复、没法审。
- **怎么做**：① **队列**先定优先级（成单 → 自牌 → 真回 → WA → 企业邮箱主区 → 其他 → 免费邮箱）；② **批文件**只写判定（`V = {编号: (结论, 理由, [(引文, URL)])}`），一眼可审；③ **共用库**负责所有落点（研究档 / sieve / 巡检表 / 日志 CSV），改一次全批受益（`lt_review_lib.run`）；④ **日志 CSV** 一行一户带批次（编号守卫去重）；⑤ **名册 / 统计**从真相源重算（`lt_roster.py`），不手数；⑥ 批号单调递增、脚本提交进仓库（可追溯、可重放）。
- **坑**：批文件里混落点逻辑；跨库户塞进同一批（External / Planet 走各自的落点脚本）；编号靠前缀猜（B 户可能仍是 `SC-`）。

### M11 · 怎么读一个客户（固定八问，输出一句理由）

- **解决什么**：「分析客户」如果每次临场发挥，结论不可比、不可复核。
- **八问**（顺序固定）：① **是谁**：法定名 / 登记状态 / 成立 / 规模 / 老板是不是联系人（底数 + KP 阶梯）；② **行业内吗**：安防 / IT / 网络 / 工业网络的分销、集成、安装、自有品牌、网店，或终端但有复购；③ **对位吗**：在卖 / 在用交换机、收发器、PoE，与主表同口型；光端机 / DWDM / 光模块为主 → `dayjob_fit` 单列；纯摄像头 / 无源 / 线缆 / 消费 → 不对位；④ **路径**：具名 KP 邮箱 > 企业 info@ > 仅 WA > 仅电话 > 仅表单；域名活不活（二次验证）；⑤ **关系深度**：成单 / 样品 / PI / 真人真回次数（扣否定回复）/ 打开 / 展会 / WA 已加；⑥ **区域与收款**：四主区 + 波兰 / 次优（俄语区、印度、韩国）/ 守界（UA / IR / SY）/ 收款待定（RU / BY / KZ / UZ）；⑦ **风险**：红旗（仲裁 / 执行 / 制裁待核）、休眠、换手、收缩、Q-33 经销体系现供；⑧ **下一步**：一型号一价一问 + 发信窗口 + 不说什么 + **可逆条件**。
- **输出句式**：`<事实 1>；<事实 2> → <结论 A/B/C 或 留B/打回C>（命中规则 xx；路径 = …；可逆 = …）`。
- **文件**：J1–J7 判读框架 `docs/Saga内在逻辑与概念_2026-10-24.md` §4；留 B / 打回判据 `docs/长期客户群_方案与复核_2026-10-29.md` §2。

### M12 · 怎么读一封邮件、一个官网、一个登记页（各抽什么）

| 对象 | 必抽 | 常见误读 |
|---|---|---|
| 一封邮件 | 方向（来 / 去）；真人还是机器（自动回复 / 退信 / 工单 / 订阅确认都不是回复）；需求原句；断点（谁欠谁一封）；写信的人与职务；报过的价与日期；`last_out`（写「现在」前先看最后一封去信） | 把 M365「Opened」当回复；把工单机器人（fiberONE NX#）当拒绝；把 Simon 备注当客户话 |
| 一个官网 | 页脚 / Impressum / 隐私页的**法定名与登记号**；在卖品牌（brands_seen）；型号样式 token；交换机 / PoE 类目是否存在；联系路径（公开邮箱 / 表单 / WA）；语言与目标市场；规模线索（sitemap 页数、多站点、多语言）；社媒 / GitHub 链接 | 品牌域当法人（lanberg.pl → Impakt S.A.）；用首页 banner 判品类；没看到就写「无」 |
| 一个登记页 | 状态；成立日；法律形式；董事 / PSC / 股东（谁拍板）；年报规模（员工 / 资产）；曾用名；抵押 / 诉讼；**同名陷阱先对地址 / 城镇 / 域名** | 同名异地；把注册代理当老板；把「休眠」当注销 |

### M13 · 「做完了没」怎么判：以原话为验收，以当前数字作答

- Simon 的问句里有动词 + 范围（「所以 AB 都审核完了 C 也审核完了 是吧」）→ 验收 = 范围内每一户都有机器可查的结论字段（`lt_review.status` / `sieve verdict` / CSV 列），回答时**跑命令取当前数字**（名册 2,045、日志 1,219、永久 pass 1,431），不用记忆里的数；对「都搞完了」永远先过 M7 维度表再说 yes，并把剩余项与「为什么还没」一起说出来。

### M14 · 被纠偏时怎么做（Simon 说「你搞错了」）

1. 先认：第一句用自己的话复述**正确**理解（让他确认你这次懂了）；2. 不辩解、不解释为什么会错（他不需要）；3. 已做的产物**不删**（仓库规则），但在台账里降为「附录 / 副产物」并说明；4. 按正确理解重做，重做前过一遍 M1；5. 总账 PR 行状态改 `⛔ 误读 → 见 PR-02-xx`，新开一行；6. 把误读的原因写成方法（本条 = T29-U133 的产物：「方法论」在 Simon 嘴里 = 怎么工作、怎么分析，不是 Saga 事实，也不是命令手册）。
