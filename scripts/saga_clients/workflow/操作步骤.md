# 客户官网快照自动化 · 操作步骤（给 Simon）

> 目的：Arena 沙箱访问不了客户网站，所以让 **GitHub Actions 的运行器**去批量抓 A/B 级客户官网（首页 + sitemap 概况 + ≤6 个产品/关于/联系子页的文本摘要），结果写回本分支 `data/saga_clients/site_snapshots/`，我再据此批量加厚 B 级 MD。
> 代理（我）的 GitHub 连接**没有 workflows 权限**，推不了 `.github/workflows/` 下的文件，所以这一步需要你在 GitHub 网页上做一次（约 3 分钟）。之后全自动。

## 一、要做的事（一句话）
把本目录的 `saga-clients-snapshot.yml` **原样**保存为仓库里的 `.github/workflows/saga-clients-snapshot.yml`（分支 `arena/3f35b9b3-planet`）。保存即自动运行。

## 二、网页逐步操作
1. 浏览器打开仓库：`https://github.com/elsasaga-cloud/Planet`
2. 左上角分支下拉框 → 选择 **`arena/3f35b9b3-planet`**（务必不是 main）。
3. 点右上 **Add file → Create new file**。
4. 在文件名输入框里输入（逐字，含点号和斜杠，输入 `/` 时 GitHub 会自动分目录）：
   ```
   .github/workflows/saga-clients-snapshot.yml
   ```
5. 把下面「三、文件内容」整段粘贴进编辑框（从 `# T27：` 开始到最后一行 `git push ...` 结束，不要漏行；YAML 对缩进敏感，粘贴后不要手动改空格）。
6. 点右上 **Commit changes…** → 提交说明填 `T27: 开启客户官网快照 workflow` → 选 **Commit directly to the `arena/3f35b9b3-planet` branch** → **Commit changes**。
7. 保存后 30 秒内，顶部 **Actions** 页会出现一个名为 **Saga Clients site snapshot** 的运行（黄色圆点 = 运行中）。点进去可看日志：`sites to snapshot: N …`、每 25 站一行进度、每 150 站一次 `pushed: T27: 客户官网快照 +150…`。
8. 全部跑完（预计 40–90 分钟，上限 5.5 小时）后，分支里会多出：
   - `data/saga_clients/site_snapshots/SA-xxx.json` / `SB-xxxx.json`（每站一份，约 1,330 份）
   - `data/saga_clients/site_snapshots/_report.json`（成功 / DNS 失败 / 超时 / HTTP 错误 / 停放页 统计）
   - `data/saga_clients/site_snapshots/_index.csv`（一行一站：状态、最终 URL、标题、子页数、页面邮箱）
9. 跑完后在对话里告诉我一句「快照跑完了」即可，我会 `git pull` 后开始批量加厚 B 级。

## 三、文件内容（原样粘贴）
```yaml
# T27：客户官网快照（A/B 级加厚挖掘的原料）。Arena 沙箱不能访问客户网站，
# 故由 GitHub Actions 运行器批量抓取首页 + sitemap 概况 + ≤6 个产品/关于/联系子页的文本摘要，
# 写入 data/saga_clients/site_snapshots/ 并分批提交回本分支（每 150 站一提交）。
# 注意：代理的 GitHub 连接没有 workflows 权限，无法把本文件推到 .github/workflows/；
# 需要 Simon 在 GitHub 网页上把本文件原样保存为 .github/workflows/saga-clients-snapshot.yml
#（分支 arena/3f35b9b3-planet），保存即自动运行（也可在 Actions 页手动 Run workflow）。
name: Saga Clients site snapshot
on:
  push:
    branches: [arena/3f35b9b3-planet]
    paths:
      - .github/workflows/saga-clients-snapshot.yml
  workflow_dispatch:
    inputs:
      grades:
        description: 抓哪些等级（逗号分隔）
        default: "A,B"
      max_sub:
        description: 每站最多子页数
        default: "6"
      force:
        description: 强制重抓（1=是）
        default: "0"
      limit:
        description: 最多站点数（0=不限）
        default: "0"
permissions:
  contents: write
concurrency:
  group: saga-clients-snapshot
  cancel-in-progress: false
jobs:
  snapshot:
    runs-on: ubuntu-latest
    timeout-minutes: 330
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 1
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install deps
        run: python -m pip install -q requests beautifulsoup4 lxml
      - name: Snapshot sites
        env:
          GRADES: ${{ github.event.inputs.grades || 'A,B' }}
          MAX_SUB: ${{ github.event.inputs.max_sub || '6' }}
          FORCE: ${{ github.event.inputs.force || '0' }}
          LIMIT: ${{ github.event.inputs.limit || '0' }}
          WORKERS: "12"
          COMMIT_EVERY: "150"
          GIT_COMMIT: "1"
          GIT_REF: ${{ github.ref_name }}
        run: |
          git config user.name "saga-clients-snapshot[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          python scripts/saga_clients/site_snapshot.py
      - name: Final commit (safety)
        if: always()
        run: |
          git config user.name "saga-clients-snapshot[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add data/saga_clients/site_snapshots || true
          git commit -q -m "T27: 客户官网快照（收尾提交 $(date -u +%Y-%m-%dT%H:%MZ)）" || { echo "nothing to commit"; exit 0; }
          git pull -q --rebase -X theirs origin "${{ github.ref_name }}" || true
          git push -q origin "HEAD:${{ github.ref_name }}"
```

## 四、以后怎么重跑 / 只跑一部分
- Actions 页 → 左侧 **Saga Clients site snapshot** → 右侧 **Run workflow** → 选分支 `arena/3f35b9b3-planet` → 可填参数：
  - `grades`：抓哪些等级，默认 `A,B`；只补 A 填 `A`。
  - `max_sub`：每站最多子页数，默认 `6`（想更细填 `10`，耗时相应增加）。
  - `force`：`1` = 已有快照也重抓（默认 `0` 只抓缺失/失败/超过 30 天的）。
  - `limit`：最多站点数，`0` = 不限（想先试跑填 `50`）。
- 同一时间只会跑一个实例（`concurrency` 已设），重复点不会并行乱写。
- 每 150 站自动提交一次，中途失败也不会丢已抓的部分；重跑只补缺失。

## 五、常见问题
| 现象 | 处理 |
|---|---|
| Actions 页没有出现运行 | 检查文件路径是否精确为 `.github/workflows/saga-clients-snapshot.yml`、分支是否为 `arena/3f35b9b3-planet`；或在 Actions 页手动 **Run workflow** |
| 运行报 `Resource not accessible by integration` / push 被拒 | 仓库 **Settings → Actions → General → Workflow permissions** 选 **Read and write permissions** 后重跑 |
| 日志里大量 `dns_fail` / `timeout` | 正常现象（老域名失效、站点屏蔽云 IP）；`_report.json` 会汇总，我按状态处理：失效域名在 MD 标「官网失效」 |
| 想停止 | 运行页右上 **Cancel workflow**；已提交的快照保留 |
