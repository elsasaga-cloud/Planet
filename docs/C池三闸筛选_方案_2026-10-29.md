## 2. 闸 0 · 刚性机筛（只认三条，宁漏勿错）

**原则：任何需要「判断」的都不进闸 0。** 命中以下任一条且**不触发任何例外**，才自动 pass_final：

| 规则 | 定义（机器可验） | 2026-10-29 命中 |
|---|---|---|
| **G0-1 无任何联系路径** | 实体无邮箱、无电话、无 WhatsApp 已加、无域名 / 网址 / 平台链接；**原始表行全文**（含备注、AI 评语列）里也没有 `@`、7 位以上数字串、网址、微信 / WeChat / WhatsApp / 已加 / 加了 / LinkedIn / Skype / Telegram / 手机 / 电话 等任何联系线索 | 见机筛报告 |
| **G0-2 退信且无备路** | 表内标「发不过去 / 退信 / bounce」，且该户**所有**邮箱域名经 DNS 查为 NXDOMAIN 或无解析（`mx_check_2026-10-29.json` status ∈ {nxdomain, dead}），且无电话、无 WhatsApp 已加 | 见机筛报告 |
| **G0-3 明确拒绝** | 表内明确记「拉黑了 / 被拉黑」（无论是客户拉黑我们还是 Simon 拉黑对方，关系都已断死）；或联系信息**明显造假**（如 `asdsd@gmail.com`、`12345678` 号码）且邮件发不过去 / 加不上 | 见机筛报告 |

**例外（命中也不 pass，转闸 1）**：成单 / 样品 / 实质回信 ≥1 / 有互动备注（engaged_note） / 加过 WhatsApp / 有电话；**乌克兰**（战时域名下线 ≠ 公司没了，Simon 明示不永久 pass）。

**明确不算闸 0 的**（全部进闸 1 人判）：
- `Spam` 备注（34+6 户）—— 多数是「谷歌找到的网站 + 无具名人」，是「发了等于骚扰」的意思，不是客户拒绝；
- 「不再跟进 / 不跟进 / 不用跟 / 暂时不跟进」（19 户）—— 是我方当时的决定（和 O 有重叠风险 / 避免摩擦 / 价格敏感 / 要 UL 等），不是客户判死；
- 「不相关 / 没用 / 无效 / 已离职」—— 品类或人事变化，不刚性；
- 「垃圾询盘」里写「像是 / 大概率」的 —— 不刚性，留闸 1；
- 域名死了但表内没退信记录（闸 0 不收，但作为闸 1 的「机筛建议 pass」优先项）。

闸 0 每次运行输出 `docs/requirements/C池闸0_机筛报告_<日期>.md`：规则计数 + **逐户清单（编号 / 公司 / 国家 / C 细分 / 规则 / 一句话依据）**，Simon 扫一眼即可否决任何一户（否决 = 在 sieve.json 把该户改 keep_C 并记 `manual: true`）。

## 3. 闸 1 · 轻量卡片（人判，三选一）

**不是加厚。** 每户 3–5 分钟，只回答五个问题，写进 `sieve.json` 的 `card`：

1. **还活着吗**：官网 / 域名活不活（mx_check + 已有官网快照 `data/saga_clients/site_digest.json` / 必要时 fetch 一次首页）；
2. **卖什么、什么角色**：分销 / 集成 / OEM 品牌商 / 终端 / 网店 / 同行；
3. **产品对不对位**：交换机（商用 / 工业 / PoE / 数据中心）对位 ✔；**视频光端机 / DWDM / 光模块 为主的 → 标 `dayjob_fit`（Simon 本职公司用得上，不 pass，留 C 或候选）**；纯 CCTV 摄像头 / 无源 / 线缆 / 消费电子 → 不对位；
4. **地区**：美 / 加 / 欧洲全域 / 土耳其 四主区 + 波兰 = 优先；俄语区 / 印度 / 韩国 = 次优；其他 = 不加分不减分；
5. **联系路径**：具名 KP 邮箱 > 企业 info@ > 仅 WhatsApp > 仅电话 > 仅网页表单。

**判定**：
- `候选`：对位 ✔ 且（主区 or 有成单 / 样品 / 实质回信 / 自有品牌 / 加过 WA 且回过）→ 进闸 2；
- `keep_C`（默认）：活着但对位弱 / 地区弱 / 只有 info@ / 巨头运营商 / 乌克兰 / Spam 备注 / 不再跟进 等一切「没判死」的；
- `pass_final`：**必须有一句话硬证据**，限于：官网 + 域名 + 社媒全死且无电话 WA；已查实注销 / 并购消失；明确拒绝；纯消费品 / 纯无关行业（如银行、律所、农场）且无任何 IT 采购迹象。

**批量与顺序**（每个长任务 ≈ 60 户；已有 research JSON 的 261 户更快）：
① 成单 29 + 样品 15 → ② 自有品牌 124 → ③ 实质回信 31 → ④ 加过 WhatsApp 429 → ⑤ 有企业邮箱、四主区 + 波兰 → ⑥ 有企业邮箱、其他区 → ⑦ 仅免费邮箱 / 仅电话 → ⑧ 「研究后定 C」44（已有 JSON，随手插队）。
机筛建议 pass 优先项（域名全死但无退信记录 ≈ 80 户）穿插处理，每批带 10 户。

**Actions 预筛**：`scripts/saga_clients/site_snapshot.py`（T27 官网快照）目前只抓 A/B；脚本可改、workflow 不可改 —— 下一步评估把「闸 1 当批 60 户」塞进快照目标，Actions 跑完再人判。评估结论另记，不先承诺。

## 5. 「P 级 / 资产池」准入（Simon 已认可的草案，闸 2 后适用；A/B 入池另议）

满足 **≥2 条**：成单或样品；决策人真回过信（实质回复）；产品对位（含 dayjob_fit）；四主区 + 波兰；登记坐实（底数查到注册号 / 地址 / KP）；复购体量（分销 / 品牌商 / 多项目集成）。
池上限 ~500，宁缺毋滥。**补充（闸 1 第 02 批后，待 Simon 认可）**：「产品对位 + 四主区」两条太容易同时满足（任何一家欧美安防分销商都是），所以——**有关系的户**（成单 / 样品 / 决策人真回 任一）≥2 条即可入池；**纯冷户**（从未回过）须 ≥4 条且必含「登记坐实」+「复购体量」，否则只打 `oem_target` 标留 C，等 OEM 专项再碰。池成员 MD 顶部加 `origin: saga | external:<repo> | planet` 与入池日期、满足条数。
