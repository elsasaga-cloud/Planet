# Saga 的内在逻辑与概念（概念层，2026-10-24）

- 定位：`docs/理解与方向_V1_深度串联_2026-10-24.html` 是**事实层**（谁、何时、多少钱、出处）；本文是**概念层**——把事实背后反复出现的结构抽出来，命名、定义、给出可观察形态，供「针对性加厚」与 A/B 客户调查直接当判读工具。小问题（E1–E26 之类）一概不在这里讨论。
- 方法：每个概念都标「出处」（Simon 文档 / 邮件 / 对话）和「在数据里长什么样」。没有出处的句子是推断，标〔推断〕。

## 0. 一句话

**Saga 卖的不是交换机，而是「一个人就能长期维持的供应关系」。** 所有看似分散的做法——Marvell 管理型口号、Drive 自助资料、Template 条款、全预付、中性包装、不做的清单、慢节奏群发、三个名字——都是同一个优化目标的解：**在一个人、无库存、无认证能力、不能打价格战、副业时间的约束下，让每个客户的维护成本最低、复购概率最高。** 出处：《背景信息》四句总纲（摘读 D12）、《总结反思》「只做顺手单不做拼命单」（A20）、《技术绑定路线》（A1）、U28/U29「省你的时间 + 有没有长期复利」。

## 1. 约束在前，策略在后

Simon 的文档从不先讲「市场机会」，先讲「我是谁、我不能做什么」。把约束列全，策略就都是推论：

| 约束（事实） | 出处 | 直接推出的做法 |
|---|---|---|
| 一个人，副业，固定成本 2–3k/年 | 《总结反思》A20；U28「三个账号都是我」 | 不能服务多客户 → 必须筛；不能做售后密集的产品 → 不做云管理/消费级；时间是最贵的资源 |
| 不压货、全预付、供应商 → 货代 | 《计划》A11；四张 PI 全 T/T·PayPal | MOQ 1、样品付费、交期随供应商；「库存」只能是供应商的芯片库存（E12） |
| 贸易商身份，价格被动 | 《背景信息》劣势项 | 不以价格竞争 → 利润底线制 + 30% 封顶 + 拒绝价格客户 |
| 认证只到 CE 级（无 UL/E-mark/KC） | 《背景信息》 | 守界：不进强制认证行业；日本/美国 UL 项目让客户自担认证（UNEA-X 问答） |
| 不做国内市场；国内单只走私账 | Saga.md 2026-08；《计划》 | 网站不写中文；与 SmartByte 国内客户冲突时让路（Larch 案） |
| 供应商关系 > 单笔机会 | U28「CENTEC 敲门砖、Peter 产品优先」；Larch 案 | 产品边界由供应商能力与 ROI 决定，不由客户需求决定 |

〔推断〕这张表就是为什么 Simon 的文档读起来「保守」：不是没有野心，而是每一项策略都受前面约束的硬限制。加厚时判断一个建议是否靠谱，先问它是否违反了左列任何一条。

## 2. 概念词典（13 个）

### C1 · 两层三供应商（Saga = 接口层）
- 定义：Saga 不是产品公司，是**接口层**——下面是三家供应商（SmartByte/Marvell、HRUI/Realtek、Hohunet/CENTEC），上面是客户；Saga 提供的是统一的型号命名、资料、条款、对接人。出处：《背景信息》第一句；供应商.xmind（摘读 D9）。
- 可观察形态：PI 上「Manufacturer: Zhengzhou Saga Telecom」+「Marvell Chip」备注；对客户说「our engineering team / our factory」（A 邮箱）；型号 STC/STI/STH 统一前缀覆盖三家来源。
- 对加厚的含义：客户感知到的「Saga 的能力」= 供应商能力 + Saga 的接口质量。判断客户问题能否解决，先查是哪一层的事（固件功能 → SmartByte；高速/许可 → Hohunet；价格 → HRUI 月变）。**不代 Simon 向供应商问价**（U29）。

### C2 · 三道筛子（过滤优先于转化）
- 定义：Saga 把「找到对的客户」做成三道被动筛子，而不是主动说服：①口号「Marvell 管理型」把只看价格的 Realtek 客户从芯片源头筛掉；②Drive 自助资料筛掉不愿读的；③Template 条款（Must-Read / A Word / Order Procedure / Warranty / Customization）筛掉不接受规则的。出处：《客户绑定情况分析》A15；Template 文件夹 A22；摘读 D1/D8。
- 可观察形态：群发附件永远是 Product Link PDF（五个 Drive 文件夹）而不是价格（A 邮箱 1,300+ 次引用）；Alan 的回复先发链接再谈；A Word 原话「只服务少数忠诚耐心专业的客户」。
- 对加厚的含义：**一个客户走到第几道筛子，就是他的真实阶段**。读了 Drive（能引用型号/价表）= 过第二道；付样品、确认 PI/标签、填供应商表 = 过第三道。这是比「回复过邮件」有效得多的分级依据。

### C3 · 顺手单 vs 拼命单（努力经济学）
- 定义：只做边际努力小、复购可能大的单；不为一次性的大单改变运营方式。出处：《总结反思》「只做顺手单不做拼命单」A20；《背景信息》「不追求快速成单」。
- 可观察形态：Larch 8,000 台（需要 $250 目标价 + 无软件 + 与国内客户冲突）被主动停止；Netaş 停滞后不改产品、只在 4 个月后再发一次特性表；ITM 400G 报价后不催。
- 对加厚的含义：评价一个 A/B 客户的价值，不是「他能买多少」，而是「服务他要改变多少现有做法」。需要新认证、新物流线、新付款方式、新固件的客户，权重要下调。

### C4 · 技术流绑定（工程延续性，不是 API）
- 定义：让客户把 Saga 的**型号、CLI/MIB、固件行为、规格书**写进自己的系统、标书、运维文档，从而产生替换成本；明确放弃 API/SDK 这类「伪绑定」。出处：《技术绑定路线》A1（5 信号 + 三问）；D1；E2。
- 可观察形态：NYNEX 向 LibreNMS 提交 OID、坚持 SmartByte OID（较深）；Go Green IT 写博客、报告 SSH 终端 bug（进入了客户的运维循环）；Netaş 把 1 台样机留在终端客户；Latmedia 要 SDK → 转介（不是绑定对象）。
- 对加厚的含义：绑定证据的层级：**样品在手 < 批量采购 < 客户文档/网站/标书出现 Saga 规格 < 客户自研系统依赖 Saga 固件/OID**。每户写绑定等级时按这个梯度找证据（监控快照、GitHub、博客、招标文件）。

### C5 · 中性与隐身（客户的品牌 = Saga 的绑定）
- 定义：设备中性、无中文、logo 只印标签；SmartByte 隐身在 Saga 之后，Saga 又隐身在客户品牌之后。出处：《俄罗斯地推反思》（摘读 D6 中期）；UNEA-X 问答第 5–7 条；PI「Non-brand packing」。
- 可观察形态：Angora「Verge」系列、Fastball FBC-204GP = STC-204GP（U18 研究档）；PI 报关写 Saga 为制造商。
- 对加厚的含义：**OEM 品牌商最优先的根因在这里**——客户为自有品牌投入的型号、包装、文档都是沉没成本，换供应商要重做。找 A/B 客户时，「有自有品牌的交换机产品线」是最强的正向信号；反之纯转售知名品牌的分销商（Sava 类）绑定最弱。

### C6 · 价格被动 → 利润底线制
- 定义：Saga 不定价、不谈价，只守底线：芯片线底线 Realtek ≥20 / Marvell ≥25 / CENTEC ≥35（《计划》），客户类型档 分销 20 / 集成 25 / OEM 30（仓库规则），封顶「给我 100 最多卖 130」（《背景信息》）。两套并存（E1），都是底线不是策略。
- 可观察形态：价格异议一律不让步（iotsistem、Aironix、case.uk）；群发里的低价是旧汇率引流价（U28）；报价单固定「15 天有效、汇率剧烈波动重新定价」。
- 对加厚的含义：客户来信里出现「target price」「extremely expensive」「cheaper alternative」而没有任何技术问题 → 价格流客户 → 降级或 PASS，不要在加厚里给他们设计「让价方案」。

### C7 · 国家 = 运行方式，不是市场规模
- 定义：一个国家能不能做，取决于**收款、物流、合规**三件事是否已有现成通路，而不是需求大小。出处：《客户国家选择》《TR 市场分析》（摘读 D3）；U28 物流两条线。
- 可观察形态：土耳其 = TRY 收款（HK 账户）+ 小批量多批次 + WhatsApp；俄罗斯 = 货代付款不走公账；尼日利亚 = 客户货代 + WhatsApp only；美国/欧洲 = PayPal/T/T + DHL/UPS DAP；日本 = PSE 电源 + 认证自担。
- 对加厚的含义：给每个 A/B 客户补一行「国家运行方式是否已通」——已通的国家，新客户的边际成本低（顺手单）；未通的国家（印度、韩国、巴西、南非），同样的询盘价值打折（E3/E11）。

### C8 · 群发 = 引流到资料，不是销售
- 定义：群发的任务是让 1% 的人点开 Drive 链接并自我筛选，不是促成回复。出处：A 邮箱结构（14,500 发 → Opened 1,011 → 真实来信 208 → 成单 4）；Opened/Replied/Daily 自建标签；U28「减少群发是战略取舍」。
- 可观察形态：主题按月换产品，附件不变；回复率低但 Simon 不改群发方式；对「请停止发送」只是移除。
- 对加厚的含义：**「回复过群发」本身几乎不含信息**。有价值的是回复的内容类型（技术问题 / 要资料 / 要价格 / 拒绝）。A 邮箱 91 条线程里真正有加厚价值的约 10–15 条，其余只需一行记录。

### C9 · 三个名字 = 一个流程的三个阶段
- 定义：Simon / Alan / Elsa 对外是三个人，对内是一个流程：首触与产品站（e.）→ 报价、PI、订单（a.）→ 早期关系与收款账户（s.）。出处：U28「三个账号都是我」；A 邮箱交接句式；Saga.md 分工。
- 可观察形态：「My friend Simon sent you some info… I will take over」；PayPal 收款在 s. 账户而 PI 由 a. 开；编号 STSC / STAG / STEC。
- 对加厚的含义：一个客户的完整历史分散在三个邮箱，**合并后才是一条线**（52 Networks 的 S 邮箱早期接触 + A 邮箱 PI）。加厚每户时三邮箱都要查，写明「最后一次由哪个名字接触」。

### C10 · 边界即资本（Not-to-Do 清单）
- 定义：明确不做的清单是让一个人持续可运营的方法，不是能力不足的清单。出处：《俄罗斯地推反思》Not-to-Do；sagatele.com「We Don't」；Alan 对 Larch「高速 Marvell 不做激进研发（技术资源与 ROI）」。
- 清单（合并）：云管理、EN50155 轨交/车载、IP67、消费级、UL/E-mark/KC 行业、SFP28/高速 Marvell、L3 组播级固件、SDK/源码、国内公账单、视频营销、Facebook/YouTube/付费广告。
- 对加厚的含义：客户需求命中清单 → 直接写「停点：边界」，不设计绕路；这类客户只在他们的需求变化时才值得再触达。

### C11 · 供应商关系优先于客户机会
- 定义：当客户机会与供应商既有利益冲突，Saga 让路；CENTEC 是敲门砖但 Peter 的产品优先。出处：Larch 案「与我们一个国内客户冲突，内部决定」；U28；T29-U15 NYNEX 安排（Saga 推 SmartByte、Peter 处理技术）。
- 对加厚的含义：A/B 客户里若发现其项目可能与 SmartByte 国内客户重叠（大型校园/运营商项目、要求无软件裸机），先标记「待 Simon 判断冲突」，不要推进。

### C12 · 慢是武器（十次不行就五年）
- 定义：因为固定成本极低、不靠 Saga 吃饭，Simon 可以等客户的替换周期；每一次触达都在增加对方的熟悉度而不增加自己的成本。出处：《背景信息》策略句；Netaş 停滞 4 个月后再发特性表；主职/股票/外贸三层结构（A20、D7）。
- 可观察形态：群发连续两年；对停滞客户不催、不让价；Template 规定每客户一个 Drive 文件夹（长期关系的容器）。
- 对加厚的含义：每户需要一个**节奏记录**（最后触达日期、触达次数、下一次合理触达的触发条件），而不是「待跟进」三个字。复活条件尽量写成外部事件（客户发新产品、招标、固件新版本、供应商新机型），而非「再发一封邮件」。

### C13 · 信息资产化（一次做好，反复使用）
- 定义：规格书、价表、用户手册、特性表、Roadmap、Profile 都按「一次做好、季度更新、所有客户共用」设计；资料既是筛子也是绑定工具也是网站内容。出处：《计划》资料体系 A11；摘读 D5；Resource Library（Roadmap.pdf、STOS V2.4、7.5.x 特性表）。
- 对加厚的含义：加厚产出也应该是**可复用的结构化字段**（绑定等级、停点、复活条件、国家通路、最后接触人），而不是每户一篇作文——这样监控脚本和下一轮加厚都能直接读。

## 4. 客户判读框架（加厚与 A/B 调查直接使用）

每户加厚只回答下面 7 个问题，每个答案必须带证据（邮件日期 / 快照 URL / 研究档字段），没有证据写「待补证」。

| # | 维度 | 取值 | 证据长什么样 | 对应概念 |
|---|---|---|---|---|
| J1 | 客户类型 | OEM 品牌商 / 有进口经验者 / 分销商 / 集成商 / 其他 | 官网有自有品牌交换机产品线（OEM）；PI/报关/货代经验、问 HS code/Incoterm（进口经验）；多品牌目录（分销）；项目案例页（集成） | C5、《背景信息》③ |
| J2 | 技术流 or 价格流 | 技术 / 价格 / 混合 / 未知 | 问 VLAN·ERPS·MIB·CLI·固件·温度·PoE 预算（技术）；只问 price list / target price / MOQ（价格） | C2、C6 |
| J3 | 走到第几道筛子 | 0 未触达 / 1 回过群发 / 2 读过 Drive（能引用型号或价表）/ 3 走过 Template（付样、PI、标签确认、供应商表、Drive 文件夹） | 邮件里引用型号或价表数字 = 2；PI 编号、付款凭证、保修证书、NDA/ECCN 表 = 3 | C2 |
| J4 | 绑定等级 | 无 / 轻度（样品在手）/ 中度（批量 + 客户文档出现 Saga 规格）/ 较深（客户系统依赖 Saga 固件·OID·CLI）/ 深（自研集成 + 多年复购） | 监控快照里的产品页、GitHub、博客、招标文件、LibreNMS 之类的提交 | C4 |
| J5 | 停点 + 复活条件 | 停点 ∈ {功能上限, 温度/认证, 价格, Saga 边界, 国内冲突, 对方不需要, 无回音}；复活条件写成外部事件 | 停点取客户最后一封实质邮件的原话；复活条件举例：「固件 7.5 补 PIM-SM」「客户发布新一代产品」「招标公告」 | C10、C12 |
