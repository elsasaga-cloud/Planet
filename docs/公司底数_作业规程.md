# 公司底数（官方工商登记）作业规程 · 2026-10-27 起

> T29-U65 Simon：「公司底数 对 就搞这个 深挖 一直挖」。本规程 = 每国免费来源、取法、能拿到什么、花多少、拿不到什么。每轮按此执行，结果只写 `data/saga_clients/registry/<国>_<来源>_<日期>.json`（`registry_store.put(code, key=<国>, ...)`），再由 `render.py`（`batch82.fmt_registry`）渲染进 A/B MD 的「第 82 批」块（行首标「第 N 批」）。

## 0. 通用规则

- **只记官方 / 准官方登记能复查的事实**：法定名、登记号、状态、成立日、法律形式、行业码、注册地、资本、高管 / 股东、年报数字、抵押 / 诉讼、曾用名。每条带来源 URL + 查询日期。
- **「这意味着什么」** 每户 3–5 条，必须从登记事实推出来（老板 = 联系人？签字权门槛？规模与付款条件？OEM 还是分销？下次复查时点）。
- **话术禁区**（延续 U62–U64）：永远不对客户说「我们查了你的登记 / 董事 / 财报」；不在信里引用对方亏损、诉讼、债务。
- 次序：A（90）→ B 欧美土 → 其余 B。C 不碰。
- 省 token：能用 JSON API 的不用网页；能用 `web_search depth 1` 摘要拿齐的不 `fetch_page`；一页超过 3 块的站（Zauba 38 块、ARES-VR 3 块）只读第 0 块或改用搜索摘要。

## 2. 每轮步骤

1. 列未做户：`python3 scripts/saga_clients/registry_store.py`（已做 code 集合）对比 A/B 按国清单。
2. 先从 `research/<code>.json` 的 `company_facts` 捞现成登记号（ИНН / NIP / KRS / IČO / CIN / P.IVA / HRB / Company No.）→ 直接走 API / 直链，跳过搜索。
3. 取数 → `registry_store.put(code, key=<国>, batch=<N>, …)`；同时写 `patches/batch<N>_kp.py`（幂等 TAG）把「老板 = 联系人？」写回 `kp[].role` / `company_facts`。
4. 渲染配方（`renumber.py --snapshot-md` → `build.py` + `render.py` → `--restore-dates` → `calendar.py` → 三审计 → `changelog.py`）→ 台账（针对性加厚 第 N 批块、README、PR-02、Q）→ commit/push。
