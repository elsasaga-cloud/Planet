## 1. 什么叫「针对性加厚」（与 T27 的「格式化加厚」区别）

| | T27 格式化加厚（已停） | 本轮针对性加厚 |
|---|---|---|
| 信息来源 | 网页搜索（公司事实 / 在卖品牌） | **S/A 邮箱全文 + PI 包 + Drive 产品资料 + 价格主表**；不做网页搜索 |
| 产出 | 公司画像、通用 P1、模板第一问 | **这户现在停在哪、为什么、对方原话、Saga 现在该推哪一款什么价、下一步一句话问什么** |
| 证据 | URL + 日期 | 每条事实 = 日期 + 方向 + 发件人 + 原话节录 + 消息 key（`mail_dump.py <编号>` 可复现） |
| 邮件样板 | 自动模板 | 有据可发的具体草稿（替代自动模板），单一 P1、一个问题、报价带快照日期 |
| 覆盖 | 全部 A/B | **只做有真实往来的户**（有实质来信 / 成交 / 样机 / 报价史），没有往来的户不碰 |

## 2. 做法（每户 15–30 分钟）

1. `cd scripts/saga_clients && python3 mail_dump.py SA-xxx --out /tmp/elsa/mail/SA-xxx.txt` → 通读来信 + 关键去信（群发推送略读）。
2. 对照 `data/pi_orders/单号对照.csv`（成交）、`data/gmail_s/attachments/text/`（PI/规格附件）、`data/价格主表.csv` / `data/hrui_STC对照表.csv` / `data/hohunet_STH对照表.csv`（能推什么、什么价）、`data/smartbyte_drive/` 规格书（功能符合性）。
3. 写 `mail_review` 块（字段见 `render.py: fmt_mail_review`）：`situation / need / breakpoint / saga_now{p1,tier,price,why,repeat,gaps} / next_move{when,channel,action,one_question} / facts[] / proof_gaps[] / draft_en{subject,body}`。
   - `saga_now.price` 写清算式（CNY × 档位 ÷ 汇率，快照日期）；Simon 已口头报过的价以 Simon 为准并注明。
   - `gaps` 必须写「做不了 / 要先向供应商核」的点（如 REST API 无、博通芯片无、DC48V 待核）。
   - `draft_en` 只在「现在就该发」的户写；等 A 邮箱材料的户留 `null`。
4. `python3 build.py && python3 render.py && python3 audit.py`，只保留有实质变化的 MD（日期行回滚）。
5. 等 A 邮箱 / Extra Info 入库后，对已做的户补 `proof_gaps` 里缺的证据，再做第二遍。
