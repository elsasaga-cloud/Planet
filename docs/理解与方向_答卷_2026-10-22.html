  1. 成交的不是「大经销商」，是「有自己项目/自己品牌的中小集成商」：Angora（TT 智慧站点）、James（给自己的客户装）、PBA、Mbata（BNSC 品牌）。他们要的是裸板/贴牌/UI 改型号/序列号规则，不是目录价。

  3. gg 的共性：一次样品/一单后没下文的，多是南亚/俄语区/非洲的价格型买家，或 PayPal 小单。这解释了为什么你 2025 后不再撒网。
  4. 地理上钱在 TR / NG / TH / DE / CA，而邮件回复率最高的北美（28%）成交反而小（Vi-Link、52 Networks）——北美人爱回信，但下单要 UL/本地库存；土耳其人不回群发，但点对点一旦进门就是项目。

6 · 「针对性加厚」我打算怎么做（等你 OK 再动手）

原则：不再往档案里堆「公司简介/网上查到的事实」；每一段加厚都必须回答四个问题并给出证据位置——①他们已经证明了什么（成交/询价/回复原句）→ ②他们到底要什么（型号、配置、价位、付款、交期、贴牌）→ ③我们给什么（具体 Saga 型号 + 档位价 + 配件 + 交期）→ ④下一步动作与触发条件（谁、什么时候、因为什么）。证据优先级：PI 包 > S/A/Elsa 邮件原句 > Clients 表跟进记录 > 官网/搜索。
分组做法例子（会写进 MD 的那种话）
第一组：20 家成单客户每家补「证据链 → 要什么 → 给什么 → 下一步」四节；把成交型号、单价、采购价、配件、贴牌要求、付款通道、货代写死；给出「下一个触发点」（固件 7.5、2.5G、BT90W、备件、季度回访）。NYNEX：2026-10-06 刚下 20 台 STC-4168XGGCM（第 5 单，往来 104 封、最近 2026-10-17）→ 下一步是 4248XGGCM / L3 10G 对比表，触发点=他们下一批站点；Angora：Türk Telekom 智慧站点首批 2,000 台 / 60 天（机型 STI-288DGGPM，曾报 5,000 台）+ 警察 RfP（首批 15 台、最低价机型）→ 用「配置档案 + 交期承诺」而不是降价去跟，最近往来 2026-07-08 已空 3 个月
第二组：有邮件回复的 A（S 邮箱 in>0）把对方原句（问价/要资料/拒绝原因）摘进档案，按原句定 P1 和价位；拒绝过的写明拒绝原因和再触达条件，不再泛跟进。4Gon（Cadmus Distribution，UK）2025-01-27：「This is not an item we would find useful」→ 档案标明不再推 16 口 PoE 管理，只在他们目录里有的品类上再碰一次
第三组：没回过信的 A只做一件事：找出一个能证明他们有需求的事实（招标、项目、产品线、职位），没有就降 B，不硬写。宁可 A 变少，也不留「看起来像 A」的空档案
B 级一行：为什么是 B、什么事件会让它变 A（例如「买过一次 → 2026 固件更新信有回复」）。不做网页挖掘
产出形式仍由 research JSON 渲染（不手改 MD），新增字段 proof[] / want{} / offer{} / next{}；A 邮箱入库后同一套脚本再跑一遍把 A 账号的往来并进去。先做 TR 全部 + 20 家成单 + NA/EU 有回复的 A ≈ 40–50 家
